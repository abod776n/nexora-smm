# TOTA SMM — لوحة خدمات السوشيال ميديا

متجر كامل لخدمات وسائل التواصل الاجتماعي: واجهة للعميل، محفظة ورصيد، طلبات، ولوحة تحكم للإدارة، مربوط بمزوّد **Tota** (`bot.tota.click`).

## ما الموجود

- كتالوج الخدمات (311 خدمة / 12 منصة) مع بحث وتصنيفات.
- تسجيل ودخول آمن (scrypt + جلسات في قاعدة البيانات).
- طلب مباشر: اختيار الخدمة، الرابط، الكمية، خصم تلقائي من الرصيد، وإرسال للمزوّد.
- تتبّع حالة الطلب (Pending / In progress / Completed…) مع تحديث يدوي.
- محفظة: طلب شحن برقم عملية، ومراجعة من الإدارة (موافقة/رفض).
- شحن تلقائي بنجوم تيليجرام (Telegram Stars) عبر بوت المتجر، مع ربط الحساب بكود لمرة واحدة.
- لوحة تحكم: إحصاءات، رصيد المزوّد، الطلبات، الشحن، المستخدمون، الخدمات (إيقاف/هامش)، الإعدادات.
- هامش ربح عام أو مخصص لكل خدمة.
- تنسيق عربي RTL، متجاوب مع الجوال.

## التشغيل

```bash
cp .env.example .env      # ثم عدّل القيم
npm install
npm start
```

يفتح على `http://localhost:3000`.

المتطلبات: Node.js 22.9 أو أحدث. قاعدة البيانات عبر `@libsql/client`: ملف SQLite محلي للتطوير، أو **Turso** المستضاف عند النشر (البيانات تبقى حتى لو مسح الخادم ملفاته).

## متغيّرات البيئة

| المتغير | الوصف |
|---|---|
| `PORT` | منفذ الخادم (افتراضي 3000) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | حساب الإدارة الأول، يُنشأ عند أول تشغيل |
| `TOTA_API_URL` | رابط API المزوّد |
| `TOTA_API_KEY` | مفتاح المزوّد — لا تشاركه |
| `SECURE_COOKIES` | `1` عند النشر على HTTPS |
| `TURSO_DATABASE_URL` | رابط قاعدة Turso (`libsql://…`). غير مضبوط = ملف محلي |
| `TURSO_AUTH_TOKEN` | توكن Turso |
| `DATA_DIR` | مجلد قاعدة الملف المحلي (افتراضي `data/`) — يُستخدم فقط بدون Turso |
| `STORE_BOT_TOKEN` | توكن بوت المتجر من @BotFather — يفعّل النجوم وربط الحساب. **ليس** `BOT_TOKEN` (ذاك لبوت المساعد الشخصي) |
| `STORE_BOT_USERNAME` | اسم بوت المتجر بدون @ — يُقرأ تلقائياً من `getMe` إذا تُرك فارغاً |

## النشر — مجاناً بدون دومين

**Render (خادم)** + **Turso (قاعدة)** — كلاهما مجاني ولا يحتاج بطاقة. رابط الموقع يصير `https://<name>.onrender.com`، والدومين الخاص يُضاف لاحقاً من إعدادات Render.

1. أنشئ قاعدة على turso.tech، ثم:
   ```bash
   turso db create tota-smm
   turso db show tota-smm --url          # → TURSO_DATABASE_URL
   turso db tokens create tota-smm       # → TURSO_AUTH_TOKEN
   ```
2. ارفع المشروع إلى GitHub (بدون `node_modules` و`data` و`.env`).
3. في Render: New → Web Service → اربط المستودع.
   - Build: `npm install`
   - Start: `npm start`
   - Health check: `/healthz`
4. أضف متغيّرات البيئة من `.env.example`، وبالتأكيد:
   `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` و`TOTA_API_KEY` و`SECURE_COOKIES=1`.
5. أول تشغيل ينشئ الجداول وحساب الإدارة تلقائياً، ثم تُزامن الخدمات من تبويب «الخدمات» في اللوحة.

ملاحظة: القرص المجاني في Render مؤقت — لذلك قاعدة Turso ضرورية هناك. على VPS عادي يكفي `DATA_DIR` مع نسخ احتياطي دوري من `app.db`.

## تدفّق الطلب

1. العميل يشحن رصيده (طلب + مرجع تحويل) → الإدارة توافق → يُضاف الرصيد.
2. العميل يطلب خدمة → يُخصم السعر → يُرسل الطلب للمزوّد → يُحفظ رقم الطلب.
3. لو فشل الإرسال: يُعاد المبلغ تلقائياً ويُعلَّم الطلب `Failed`.
4. الحالة تُحدَّث من «حسابي» أو من لوحة الإدارة.

## الدفع

النسخة الحالية تعتمد الشحن اليدوي (تحويل + مرجع + موافقة الإدارة) — يعمل مع أي وسيلة دفع محلية بدون حسابات تجارية.

### نجوم تيليجرام (XTR)

النجوم لا تُدفع من صفحة ويب — تحتاج بوت تيليجرام. الخطوات:

1. أنشئ بوتاً من @BotFather (`/newbot`) واحفظ توكنه.
2. ضع التوكن في `STORE_BOT_TOKEN`.
3. شغّل الموقع: البوت يعمل بالـ long polling داخل نفس العملية، بلا webhook ولا رابط عام.
4. العميل يفتح «حسابي» → ينسخ كود الربط → يرسل `/link CODE` للبوت → `/add` لاختيار باقة نجوم.

الرصيد يُضاف فوراً عند `successful_payment` (سعر النجمة يُضبط من الإعدادات: `star_usd`). كل عملية تُسجَّل في `stars_payments` بمعرّف فريد، فلا تتكرر. الباقات: 50 / 100 / 250 / 500 / 1000 / 2500، مع زر «عدد مخصص» لكتابة أي عدد من النجوم (1 – 100000).

### إيداع المحافظ عبر البوت (`/deposit`)

البوت يعرض محافظ الشحن من إعداد `topup_wallets`، ويطلب المبلغ ثم رقم العملية ثم صورة الإشعار. يُنشأ طلب إيداع `pending` ويصل للإدارة في تيليجرام مع الصورة وزرّي «موافقة / رفض»؛ بضغطة موافقة واحدة يُضاف الرصيد ويُبلَّغ العميل. رقم العملية والصورة محفوظان في جدول `deposits` (`reference`, `photo_file_id`).

التحقق التلقائي 100% من تحويل محفظة (جيب أو غيرها) غير ممكن بدون API تجاري من مزوّد المحفظة، لأن رقم العملية وحده قابل للتزييف. عند توفّر API للمزوّد يكفي استدعاؤه في مسار التحقق ثم إضافة الرصيد بنفس منطق الموافقة.

ملاحظة Render المجاني: الخادم ينام بعد خمول، والبوت معه — أول رسالة بعد النوم قد تتأخر حتى يستيقظ. خدمة مدفوعة أو ping دوري يحلّ ذلك.

لإضافة بوابة دفع تلقائية لاحقاً: نقطة الدخول هي جدول `deposits` ومسار `/admin/deposits/:id/approve` — يكفي أن تنشئ مسار webhook يتحقق من الدفع ثم يضيف الرصيد بنفس المنطق.

## الحماية

- كلمات المرور scrypt، الجلسات httpOnly + SameSite=Lax.
- فحص Origin لكل POST (حماية CSRF أساسية).
- كل استعلامات SQL بمعاملات (لا حقن).
- الاستجابة تُهرَّب قبل الإخراج (لا XSS).
- لا تُخزَّن بيانات بطاقات — لا بوابة بعد.

## الخطوة التالية

بوت تيليجرام يستخدم نفس الـ API ونفس قاعدة البيانات: تسجيل بحساب الموقع، عرض الخدمات، الطلب، والرصيد. جاهز للإضافة عند توفر توكن البوت.
